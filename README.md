# 智能助理学院（dsh-learning-academy）

给 DSH 装一条「真正学会一份资料」的链路：原文切成片段账本，逐片精读，
九项确定性校验不过就回退重拆，人工复核点头之后才出题、绑定溯源并写入
知识库与 ReMe 长期记忆。课堂本身是一个对话框，每一步都落盘、可断点续。

## 插件是什么

一个可整体装卸的本地插件（`dsh-learning-academy`，v0.8.0），Host 与客户端半边在同一个包里：

| 半边 | 内容 |
|---|---|
| Host | 4 个工具（`learn_document` / `learn_status` / `learn_correct` / `learn_reindex`）、2 个命令（`/learn`、`/learn-status`）、`/academy` 页面与全部 `/api/academy/*` 接口、学习引擎与教材库 |
| Client | `lib/client.js`：左侧栏「智能助理学院」入口 + 主界面里的学院页框（`dsh.client` 声明） |

- **零 npm 依赖**：只用 Node 内置模块，模型调用走 `ctx.llm`，长期记忆走 ReMe 的 HTTP 接口；
- **数据在插件外**：课堂 `~/.dsh/learning`、知识库 `~/.dsh/academy-knowledge`、记忆 ReMe 工作区，停用插件不丢数据；
  安装包本身**不含任何学习数据**，别人装上是从零开始的空知识库；
- **整包装卸**：从 profile 的依赖与 `dsh.profile.bundles` 删掉它，工具、命令、页面、接口、侧栏入口一起消失。
- **使用说明**：见 [GUIDE.md](GUIDE.md)，并已注册为运行时技能 `learning-academy`（模型按需加载）。

### 功能一览

1. **教材库**：上传即入库（零模型调用）、多附件、换版升版本、旧版与旧课堂保留、卡片摘要、查看原件/抽取文本；
2. **学习闭环**：定边界 → 通读建框架 → 通读后答疑 → 拆条款 → 分片登记 → 逐片精读（带框架）→ 精读后答疑 → 综合核对 → 九项校验+质量审查 → 出题库 → 闭卷抽考 → 人工复核 → 绑定溯源 → 入库；
3. **课堂对话**：学员按笔记回答、允许闲聊、判读并记录课堂知识、模型可要求补检索；
4. **题库与考核**：约每 100 字一题、抽 15% 闭卷考、批量判卷、三轮回退、人员试卷与答案导出；
5. **入库**：知识库文件（笔记+题库+溯源+试卷）、ReMe 逐字分段读回、主题索引、学习台账、旧版归档、勘误记录；
6. **知识成长**：课堂优先引用、会话更正先登记再确认、同源跳过、版本/勘误、入库查重报告；
7. **运维**：`learn_status` 看进度、`learn_reindex` 重建索引、插件热重载、旧课堂升级。

## 一条学习怎么走

```
plan（确定性排步）→ scope（定边界版本）
  → overview（先通读：逐章速读 → 汇总全文框架：主线、术语、跨章依赖、初读疑点）
  → clarify-early（通读后的疑点先答一轮，别让术语理解错带偏精读）
  → map（按章拆条款）→ read（分片登记）
  → absorb（逐片精读，每片都带着初读框架读）
  → clarify（精读中新增的疑点逐条答）
  → reconcile（综合核对：拿笔记回头对框架，找冲突、纠正初读偏差）
  → validate（九项确定性校验 + 笔记质量审查，不过→只回退失败分片/重做理解）
  → quiz（按原文密度出题库：约每 100 字一题，按章节分摊）
  → exam（分章分层抽考，闭卷只用笔记作答，批量判卷）
  → review（人工复核：笔记 + 题库 + 抽考结果 + 全局理解）
  → bind（双向溯源）→ commit（入库 + ReMe）
```

**为什么先通读**：人的理解顺序是先有整体框架、再逐条细读。没有框架就逐片理解，
术语和口径容易跑偏（第 5 章才定义的术语，第 2 章已经在用），逐片笔记看着都对、合起来是散的。
所以「通读建框架」排在拆条款与精读之前，精读时把框架一起喂给模型；
精读之后再用「综合核对」回头验框架，并记录初读纠正。

计划由原文账本算出来（`lib/plan.js`），不让模型「规划」：步骤顺序可复现，
执行器只跑依赖全部完成的那一步，跑不过就退回该步并累计尝试次数，
超过上限整堂课停下等人工，**绝不跳步继续**。

抽考不过就退回错题涉及的分片重学，最多三轮；三轮不过整堂停下等人工，
绝不带着没学懂的内容去复核、入库。**考核通过之后才复核，复核通过之后才入库。**

## 九项确定性校验

| 检查 | 判据 |
|---|---|
| 原文封条 | 原文哈希与字数与开课一致，中途换文本直接拦下 |
| 片段覆盖 | 每个实质性片段（条款/表格行/列表项/段落）都被知识点引用 |
| 引用可溯源 | 每条知识点的原句逐字落在它声称的片段里 |
| 硬指标齐全 | 原文抽出的数值+单位、条款号、型号编码，笔记里一个都不少 |
| 表格行 | 每一行表格都有落点（行首字段出现在笔记或题目） |
| 笔记字数 | 高密度文档：有效字数 ≥ 原文 2 倍；引用与逐字复制不计 |
| 说明充分 | 每条至少两个实质说明字段（条件/例外/判据/示例/易错）且解释 ≥ 40 字 |
| 疑点闭环 | 学员提的疑点全部有答复或明确标成「原文没写」 |

密度按原文客观指标判定（规则句占比、每千字硬指标、表格行、条款数），
低密度文档不设比例门，但覆盖与硬指标照旧。

## 笔记质量审查（字数够 ≠ 理解了）

除了覆盖与硬指标，还会查「是不是只把原文换个说法」：

| 检查 | 判据 |
|---|---|
| 复述比例 | 与原文逐字重合的字数占比 ≤ 20% |
| 解释深度 | 每条解释字数中位数 ≥ 60 |
| 套话重复 | 两条解释的 3-gram 重合度超过 0.8 的占比 ≤ 4% |
| 全局理解 | 通读理解这一步产出的主线覆盖全部章节，冲突必须带原文原句 |

全局理解不过就重做通读理解；其它项不过就退回对应分片重写。

## 抽考（题库不全考，只抽）

- 题库按原文密度出：约每 100 字一题，按章节字数分摊；
- 抽考默认抽题库 **15% 左右**（下限 4 题、上限 `examSample`），按章节分层，高风险题至少三分之一；
- **闭卷**：学员只拿自己笔记里与该题片段相关的条目逐题作答，不给原文；
- **批量判卷**：全部答完后一次性判（N 次作答 + 1 次判卷，而不是每题两次）；
- 判分对照原文片段与判分关键词；判分关键词里的「带单位的量」没答到直接不及格；
- 整轮通过率低于结课线就退回复习，最多三轮，之后停下等人工。

## 题库也给人员考核用

题库同时产出两份可以直接用的文件（课堂目录与知识库各一份）：

- `<标题>.exam.md`：**人员考核试卷**——只含题干与答题区，闭卷、按题数给建议时长、每题均分，可直接打印；
- `<标题>.answer-key.md`：**答案与判分要点**——每题判分关键词（逐字来自原文）、判分要点、对应片段，内部判分用；
- 页面上的「导出试卷 / 导出答案」可直接下载这两个文件。

## 课堂里和学员对话，模型先理解再查再答

课堂是**模型和助教的对话**：每条发言先交给学员模型，它自己理解这句话、判断该怎么回，
需要更多材料时可以要求补检索（最多再取一轮原文），然后给出回答。

代码只做两件事，不替模型决定「只能怎么回」：

- **给材料**：把相关原文片段、相邻上下文、笔记里相关条目打包给它；
- **校验**：回答里的 `⟦S####⟧` 必须来自给它的材料，数字不能凭空出现；越界就退回确定性证据回答。

所以：

- 闲聊：模型自然回应，不进笔记、不触发重学；
- 提问：模型用材料回答，能答就答；材料里没有才说「原文没有规定」；
- 含知识（补充/纠正）：模型自己判断并说清记下什么，能对上原文的标片段，对不上的标「课外补充」，并按片重学。

没有模型通道时，才退回确定性路径，规则是：

- 先把问题拆成关键词（去掉「是不是/一定/什么」这类虚词）；
- 在原文片段里找命中，整词没出现就退到子词（「红色字体」→「字体」，「附件物料」→「附件」），
  并把命中处的上下文截出来；
- 确定性结论先成型：有规定就引原句，没规定就明说「原文没有规定」并列出原文只写了什么；
- 数量型问题（几大类/多少种/几步）不拿「几」逐字匹配，而是按数量+单位找原文的枚举句，
  把包含它的整句引出来（例如「……六大类正确归类」）；
- 模型只负责把结论讲顺，回答必须保留 `⟦S####⟧` 引用、不得出现证据里没有的数字，
  否则退回确定性答案；
- 提问与回答都进课堂实录，**并作为「课堂补充」写进定稿笔记**；助教的纠正同样进笔记，
  能对上原文的标片段，对不上的标「课外补充」，不冒充本课规定。

## 知识成长机制：课堂优先、更正需确认

- **引用优先级**：课堂精读笔记（ReMe 里的 `learn-*` 分段、知识库 `docs/learned/<标题>.md`）是第一引用，
  每条结论都能用 `⟦S####⟧` 回查原文；其它会话记下的知识点只作参考，引用时要标明来源、不得覆盖课堂口径；
  课堂笔记没覆盖的问题才用其它知识回答，并说明「课堂笔记未覆盖」。
- **更正流程**（不静默改已复核的笔记）：
  1. 任何会话发现课堂笔记有误，调用 `learn_correct` 登记「待确认」提案（原来是什么、应改成什么、依据）；
  2. 用户确认：带 `decision=accept` 才执行，`reject` 只记录驳回，笔记不动；
  3. 采纳后：更正写进课堂补充 → 回退受影响分片 → 复核结论作废 → 重走校验、题库、抽考、复核；
  4. 复核通过并重新交付后，知识库与长期记忆才更新。
- 这套规则本身也写进了长期记忆（`digest` 里的引用优先级条目），其它会话检索时能看到。

## 原文与课件更新

- **保存原文**：导入时保存抽取后的 `source.md`，同时把上传的原件复制到课堂目录 `original/`，
  记录文件名、字节数与哈希（`st.sourceFile`）；课堂与课程卡片上都有「查看原文」。
- **查看原件**：课程卡片的「查看原文」**直接打开**，不下载——PDF/图片内嵌原始字节；
  Word/PowerPoint/Excel 先生成一份 PDF 预览（按文件缓存，只转一次，之后秒开），
  预览窗口里有「下载原件」，下载到的才是上传的那份文件（逐字节一致，附 sha256 前 12 位可核对）；
  另提供「查看抽取文本」，看的是逐字抽取后的全文，不是卡片摘要。
- **同一份原文不重复学**：原文哈希相同且已结课的，直接复用已有课堂，不再学一遍、不再写记忆。
- **课件更新 = 新版本**：重新导入同名课件时，自动找同标题的上一版，记为第 2 版，
  并算出「新增 / 删除 / 未变」的片段数；旧课堂与旧笔记冻结保留，新版本重新走全流程与复核。
  知识库交付文件带版本行（第 N 版 + 原文 sha），已确认的更正写进「勘误记录」；
  覆盖旧文件前把旧版归档到 `learned/archive/<标题>-<旧版哈希>.md`，历史不丢。
- 为什么不做"只重学变化的分片"：片段 id、笔记引用、题库、溯源全部绑定在旧账本上，
  局部替换会打乱映射；全量重学更稳。增量重学是后续优化项。

## 重建检索索引

- 入库默认只重建 **BM25**（`reindexScope: bm25`），向量由 ReMe 服务增量嵌入，日常不用手动重建；
- 学院页右上角「**重建索引**」按钮：重建向量（embedding），完成提示耗时与索引块数；
- 模型也可调用 `learn_reindex`：默认 `embedding`，可选 `bm25` / `tag` / `all`（`all` 会重新嵌入全部块，只在用户明确要求时用）；
- 什么时候需要：重启 ReMe 后怀疑索引不一致、新内容搜不到、语义命中明显变差、批量改过历史笔记。

## 人工复核

`enableManualReview: true`（默认）时，**抽考通过之后**课堂停在 `review`：
- 呈现的是对账簿（覆盖率、字数比、缺失硬指标、质量审查、全局理解、题库与抽考结果、疑点）；
- 通过：锁定当前笔记哈希，随后绑定溯源、写进知识库与长期记忆；
- 退回：只重做意见涉及的分片，改完重新校验、重新补题、重新抽考、重新复核；
- 复核后笔记再被改动，之前的「通过」立即失效。

## ReMe 里存的是全文，不是摘要

长期记忆保存的是定稿笔记的**逐字切片**，按知识点边界切成若干段，段与段首尾相接：

- 每段正文就是笔记原文，说明信息放在 ReMe 的 `name`/`description`/`metadata` 里；
- 另存一份「重建清单」，列出每段的名称、字符数与 sha256，以及全文哈希与完整文件路径；
- 写入后用 `/read` **逐段读回**，剥掉 ReMe 的前置元数据后与写入内容逐字比对哈希，
  任何一段读回不一致就判入库失败，并把缺哪段、哪段不一致写进交付报告；
- 笔记复核后被改过（哈希对不上）直接拒绝入库；
- 内容变了重新交付时，先删掉上一版的分段，避免旧口径留在记忆里被检索到；
- 引用与题库单独成段，判分关键词同样可回查原文片段。

## 配置（cordis.yml / profile patch）

| 键 | 默认 | 说明 |
|---|---|---|
| `engine` | `v2` | `v1` 回到旧的七段授课引擎（旧课堂仍可用） |
| `chunkChars` | 1600 | 每片原文字数上限，越小越细、调用越多 |
| `noteRatioTarget` | 2 | 高密度文档的笔记倍数门限 |
| `enableManualReview` | true | 复核门；关掉会自动出题入库 |
| `maxAttempts` | 3 | 同一步骤最多尝试次数，超限整堂停下 |
| `concurrentChunks` | 2 | 同一次推进里并发精读的分片数 |
| `quizBatch` | 6 | 每批出题的条款数 |
| `examSample` | 20 | 每轮抽考题量（题库按约每 100 字一题生成） |
| `memoryPartChars` | 4000 | ReMe 每条记录的字数上限（只在知识点边界处切） |
| `maxSourceChars` | 60000 | 单课原文上限，超了要求拆课 |
| `autoCommit` | true | 复核通过后自动入库 |

路径类配置（`knowledgeRoot` / `stateRoot` / `skillsRoot` / `attachmentsRoot`）不写死：
不配时按当前用户目录推导（`~/.dsh/...`），换机器/换用户不用改插件文件；profile 里可覆盖。

## 发布到插件市场

DSH 插件市场是**索引驱动**的：市场读一份 format 1 的 JSON，里面列出插件名、版本与安装来源（npm 或 git commit）。

1. 把本包推到 git 仓库（或发布到 npm）；
2. 生成索引：
   ```sh
   node scripts/make-market-index.mjs --repo https://github.com/<org>/<repo>
   ```
   会从 `package.json` 取版本、从 git 取 commit 与包路径，生成 `market-index.json`；
3. 把 `market-index.json` 放到一个 HTTPS 地址（静态站/内网服务器都行）；
4. 在「插件市场 → 发现」里添加这个 URL，搜到「智能助理学院」后安装。

新机器上需要：Python 3 + `python-docx` / `pymupdf` / `python-pptx`（或配 `pythonExe` + `pyLibs`）；
ReMe 可选（不装则长期记忆未写入，其余功能正常）；Office 预览可选 LibreOffice。

## 自检

```sh
node lib/ledger.js --selftest   # 切片、覆盖、硬指标、反抄、密度
node lib/plan.js --selftest     # 计划顺序、依赖、回退上限
node lib/engine.js --selftest   # 九阶段推进、校验回退、复核门、断点恢复、课堂问答
node lib/commit.js --selftest   # 交付文件、全文分段入库、读回比对、旧段清理
node lib/classroom.js --selftest
node lib/library.js --selftest
node lib/teaching.js --selftest # 旧引擎
```

## 旧课堂升级

旧引擎（v1）开的课堂不会自动迁移：对话记录保留，但学习结论不作数。
在 v2 下调用 `POST /api/academy/classroom {action:'upgrade', id}` 会重新切账本、

## 已知限制

- docx 的自动编号由 Word 生成，抽取时按列表项保留结构、编号需回看原件；
  图片、脚注、页眉页脚不进入正文，抽取会在课堂里明确告警；
- PDF 扫描页没有文字层时会逐页告警，需要 OCR 后重学；
- 推理模型会把预算花在思考上：调用失败于 `finish=length` 时会自动加预算重试，
  仍失败就明确报错，不把思考内容当答案；
- 单课上限 6 万字，更长的规范要按章节拆成多门课。
